# FlowCraft — راهنمای پیاده‌سازی از صفر تا صد

سند مشاوره فنی بر پایه README پروژه (طراح BPMN با Angular، Node.js و MongoDB)

## ۱. خلاصه اجرایی

FlowCraft یک طراح گردش‌کار BPMN است. کاربر workflow می‌سازد، دیاگرام را با bpmn-js ویرایش می‌کند، خروجی به‌صورت XML در MongoDB ذخیره می‌شود و بعداً دوباره باز و ویرایش می‌شود. دامنه MVP عمداً کوچک است و همین نقطه قوت اصلی پروژه است.

این سند ۱۳ آیتم نقشه راه README را به **۱۰ فاز** با خروجی مشخص و معیار پذیرش تبدیل می‌کند. در پایان هر فاز یک نسخه قابل اجرا و قابل تست دارید.

**توجه:** این سند فقط بر پایه متن README نوشته شده و کد ریپو بررسی نشده است. فرض شده پوشه‌ها `frontend` و `backend` هستند. اگر ساختار واقعی فرق دارد، فقط مسیرها را تطبیق دهید.

## ۲. تحلیل وضعیت فعلی

**نقاط قوت**

- دامنه روشن و کوچک؛ موارد خارج از MVP (احراز هویت، همکاری چندنفره، موتور اجرا، نسخه‌بندی) صریحاً کنار گذاشته شده‌اند.
- پشته مدرن و منسجم: Angular standalone و Signals، TypeScript، Express، Mongoose.
- اصول طراحی درست: جداسازی لایه‌ها، قرارداد API روشن، تست قبل از بستن هر قابلیت.

**نکات قابل بهبود**

- نقشه راه کاملاً بدون تیک است؛ پس باید از فاز ۰ شروع کنیم.
- نام پروژه و آدرس ریپو یکی نیست (README از FlowCraft می‌گوید ولی دستور clone به `bpmn-io` اشاره می‌کند). پیشنهاد: یک نام واحد انتخاب و در README، package.json و ریپو یکسان کنید.
- لایسنس مشخص نشده است. برای پروژه portfolio، MIT انتخاب ساده‌ای است.
- README دستورها را مشروط نوشته است. بعد از پیاده‌سازی، دستورهای قطعی جایگزین شوند.

## ۵. فازبندی پیاده‌سازی

### فاز ۰ — آماده‌سازی محیط و ریپو

1. نام نهایی پروژه را تعیین و ریپو را مرتب کنید (LICENSE، .gitignore، .editorconfig، .nvmrc).
2. شاخه‌بندی ساده: `main` همیشه سالم، هر قابلیت در `feat/...`.
3. فایل `docker-compose.yml` برای MongoDB بنویسید و با یک دستور بالا بیاورید.
4. ESLint و Prettier را برای هر دو بخش تنظیم کنید.

**معیار پذیرش:** با clone تازه و دو دستور، دیتابیس و ابزارها آماده‌اند.

### فاز ۱ — اسکلت بک‌اند

1. پروژه TypeScript با حالت strict بسازید (اسکریپت‌های dev، build، start).
2. Express را نصب و `app.ts` را با middlewareهای پایه بنویسید: json، cors، لاگ ساده.
3. متغیرهای محیطی را با Zod اعتبارسنجی کنید تا نبود `MONGODB_URI` همان لحظه شروع خطا بدهد.
4. اندپوینت `GET /api/health` را پیاده کنید.

**معیار پذیرش:** `/api/health` پاسخ ۲۰۰ می‌دهد و یک تست supertest برایش وجود دارد.

### فاز ۲ — مدل داده و API ورک‌فلو

مدل Mongoose پیشنهادی:

```ts
const workflowSchema = new Schema(
  {
    name: { type: String, required: true, trim: true, maxlength: 120 },
    description: { type: String, trim: true, maxlength: 500 },
    bpmnXml: { type: String, required: true },
  },
  { timestamps: true },
);
```

برای لیست، فیلد `bpmnXml` را select نکنید (سنگین است) و فقط در جزئیات هر workflow برگردانید.

| عملیات | موفق | خطاها |
| --- | --- | --- |
| GET /api/workflows | 200 | 500 |
| GET /api/workflows/:id | 200 | 400 (id نامعتبر)، 404 |
| POST /api/workflows | 201 | 400 (اعتبارسنجی)، 413 (حجم زیاد) |
| PATCH /api/workflows/:id | 200 | 400، 404، 409 (تداخل نسخه) |
| DELETE /api/workflows/:id | 204 | 400، 404 |

قالب یکسان خطا: `{ error: { code, message, details? } }` و همه خطاها از یک error handler مرکزی عبور کنند.

**معیار پذیرش:** همه اندپوینت‌ها با تست یکپارچه (supertest و mongodb-memory-server) پاس می‌شوند.

### فاز ۳ — اسکلت Angular

1. پروژه Angular را با standalone و SCSS بسازید و strict را فعال نگه دارید.
2. مسیرها را با lazy loading برای سه feature تعریف کنید: dashboard، workflows، designer.
3. یک `WorkflowApiService` با HttpClient بنویسید و مدل‌های TypeScript را با قرارداد API هم‌خوان کنید.
4. یک HTTP interceptor برای تبدیل خطاهای API به پیام قابل‌نمایش بنویسید.
5. فایل `proxy.conf.json` را به بک‌اند وصل کنید.

**معیار پذیرش:** اپ بالا می‌آید، ناوبری کار می‌کند و `/api/health` از فرانت صدا زده می‌شود.

### فاز ۴ — داشبورد و مدیریت workflow

1. وضعیت لیست را با Signals نگه دارید: workflows، loading، error.
2. چهار وضعیت را پوشش دهید: در حال بارگذاری، خالی، خطا، موفق.
3. ساخت و تغییر نام با Reactive Forms و اعتبارسنجی (نام الزامی، حداکثر ۱۲۰ نویسه).
4. حذف با دیالوگ تأیید.

**معیار پذیرش:** کاربر بدون ورود به دیزاینر می‌تواند workflow بسازد، تغییر نام دهد و حذف کند.

### فاز ۵ — ادغام bpmn-js در دیزاینر

استایل‌های bpmn-js را در بخش styles فایل `angular.json` اضافه کنید: `bpmn-js/dist/assets/diagram-js.css` و `bpmn-js/dist/assets/bpmn-font/css/bpmn.css`.

```ts
import BpmnModeler from 'bpmn-js/lib/Modeler';

@Component({
  selector: 'app-bpmn-canvas',
  standalone: true,
  template: `<div #host class='canvas'></div>`,
})
export class BpmnCanvasComponent implements AfterViewInit, OnDestroy {
  private host = viewChild.required<ElementRef<HTMLDivElement>>('host');
  private modeler?: BpmnModeler;

  ngAfterViewInit() {
    this.modeler = new BpmnModeler({ container: this.host().nativeElement });
  }
  ngOnDestroy() {
    this.modeler?.destroy();
  }
  async load(xml: string) {
    await this.modeler!.importXML(xml);
  }
  async getXml() {
    const { xml } = await this.modeler!.saveXML({ format: true });
    return xml;
  }
}
```

نکات مهم:

- ارتفاع `.canvas` را صریحاً با CSS تعیین کنید؛ در غیر این صورت بوم دیده نمی‌شود.
- حتماً در `ngOnDestroy` متد `destroy()` را صدا بزنید تا نشت حافظه نداشته باشید.
- برای workflow جدید یک XML خالی پایه (شامل یک start event) به‌عنوان قالب اولیه بسازید.
- bpmn-js فقط سمت مرورگر اجرا می‌شود؛ اگر SSR فعال است، بوم را از آن جدا نگه دارید.

**معیار پذیرش:** کاربر روی بوم عنصر اضافه می‌کند و با یک دکمه XML فعلی را می‌گیرد.

### فاز ۶ — ذخیره و بازگشایی

1. دکمه ذخیره: `saveXML` و سپس `PATCH` با XML. هنگام ذخیره، دکمه غیرفعال و نشانگر بارگذاری فعال باشد.
2. باز کردن workflow: دریافت جزئیات با `GET` و سپس `importXML`.
3. نشانگر تغییرات ذخیره‌نشده و هشدار هنگام خروج از صفحه.
4. به‌روزرسانی فراداده (نام و توضیح) بدون دست‌زدن به XML.
5. برای پاسخ ۴۰۹ پیام روشن نمایش دهید (کسی در تب دیگر ذخیره کرده است).

**معیار پذیرش:** ذخیره، بستن مرورگر، بازکردن دوباره و دیدن همان دیاگرام.

### فاز ۷ — اعتبارسنجی و مدیریت خطا

1. خطاها و هشدارهای `importXML` را به پیام قابل‌فهم تبدیل کنید.
2. قواعد ساده قبل از ذخیره: حداقل یک start event و یک end event و نبود عنصر بدون اتصال. برای قواعد بیشتر از bpmnlint استفاده کنید.
3. در سرور، XML دریافتی را با bpmn-moddle پارس کنید و برای XML نامعتبر خطای ۴۰۰ برگردانید.
4. خطاهای شبکه و سرور را با Snackbar یا Toast نمایش دهید.

**معیار پذیرش:** XML خراب هیچ‌وقت ذخیره نمی‌شود و کاربر دلیل را به زبان ساده می‌بیند.

### فاز ۸ — تست

- **بک‌اند:** تست واحد سرویس‌ها، تست یکپارچه API با supertest، و تست اعتبارسنجی و خطاها.
- **فرانت‌اند:** تست سرویس API با HttpTestingController، تست کامپوننت‌های لیست و فرم، و تست خطاها. کامپوننت بوم را mock کنید.
- **E2E (اختیاری):** Playwright برای یک سناریوی کامل: ساخت workflow، رسم دیاگرام، ذخیره، بازکردن.
- هدف: پوشش خوب منطق سرویس‌ها و مسیرهای خطا، نه رسیدن به یک عدد دلخواه.

### فاز ۹ — CI/CD، مستندات و انتشار

1. GitHub Actions: روی هر PR اجرای lint، test و build برای هر دو بخش.
2. Dockerfile چندمرحله‌ای برای بک‌اند، و سرو فایل‌های build فرانت از Nginx یا از خود Express.
3. استقرار نمونه: یک سرویس ابری برای اپ و MongoDB Atlas برای دیتابیس؛ قیمت و محدودیت‌ها را قبل از انتخاب بررسی کنید.
4. README نهایی با اسکرین‌شات یا GIF، دستورهای قطعی اجرا، لایسنس و لینک دمو.
5. برچسب نسخه `v1.0.0` و CHANGELOG.

**معیار پذیرش:** هر کسی با clone و دو دستور می‌تواند پروژه را اجرا کند و دمو آنلاین کار می‌کند.

## ۷. پیشنهادهای ارتقا برای محصولی کاربردی‌تر

این موارد خارج از MVP هستند و پیشنهاد می‌کنم بعد از v1.0 و به‌ترتیب اولویت اضافه شوند.

**نسخه ۱.۱ — راحتی کار روزمره**

- ذخیره خودکار (auto-save با debounce) و نشانگر وضعیت ذخیره.
- خروجی XML، SVG و PNG و وارد کردن فایل `.bpmn` موجود.
- پنل ویژگی‌ها با bpmn-js-properties-panel.
- جستجو، مرتب‌سازی و برچسب (tag) برای workflowها.
- حالت تاریک و واکنش‌گرایی برای نمایشگرهای کوچک.

**نسخه ۱.۲ — تمایز محصول**

- تاریخچه ساده نسخه‌ها (snapshot هر ذخیره، با امکان بازگشت). نسخه‌بندی پیشرفته در README کنار گذاشته شده، اما یک نسخه سبک آن ارزش بالایی دارد.
- قالب‌های آماده فرایند (مثلاً تأیید مرخصی، درخواست خرید).
- شبیه‌سازی جریان توکن با bpmn-js-token-simulation.
- قواعد lint قابل تنظیم با bpmnlint و نمایش خطاها روی خود دیاگرام.

**نسخه ۲ — رشد**

- احراز هویت و مالکیت workflow (JWT یا OIDC) و لینک اشتراک‌گذاری فقط‌خواندنی.
- همکاری هم‌زمان چندنفره (WebSocket و CRDT مثل Yjs) و کامنت روی عناصر.
- اجرای واقعی فرایند با یک موتور BPMN (مثلاً bpmn-engine).
- دستیار هوش مصنوعی: تولید پیش‌نویس دیاگرام از توضیح متنی کاربر و ویرایش آن در دیزاینر.

**توصیه راهبردی:** چون هدف پروژه portfolio است، بعد از v1.0 دو قابلیت ذخیره خودکار و تاریخچه نسخه‌ها بیشترین نمایش مهارت مهندسی را با کمترین هزینه دارند. دمو آنلاین و یک GIF کوتاه در README هم اثر زیادی دارد.
